# Семинар № 7. Многопоточное умножение матриц

Весь код находится в `main.cpp`. В этой же папке лежат `CMakeLists.txt`,
`.clang-format`, `.gitignore` и этот README. Ядро умножения адаптировано
из [семинара № 6](https://github.com/alex6352/sem6/blob/9038cd0/src/main.cpp).

## Открытие в VS Code и сборка в WSL Ubuntu

1. Распакуйте архив и откройте папку `sem7_main` в VS Code через WSL Ubuntu.
   Из терминала Ubuntu можно перейти в эту папку и выполнить `code .`.
2. Выберите **Терминал → Создать терминал**. Выполните команды из папки
   с `main.cpp`.

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel
(cd build && ctest --output-on-failure)
```

Если инструментов нет, установите их командой
`sudo apt update && sudo apt install build-essential cmake`.

## Поэтапный запуск

Выполняйте команды по одной, чтобы записать результат каждого этапа:

1. `./build/sem7 1` — `serial`, базовое время T₁ при n = 800.
2. `./build/sem7 1` — `naive`, замер с созданием потоков.
3. `./build/sem7 3` — `gated`, замер после подготовки потоков.
4. `./build/sem7 4` — `serial`, `scale_4` и T₁/T₄ для n = 300, 500, 800, 1500.
5. `./build/sem7 5` — `ijk`, сравнение порядка циклов с этапом 3.
6. `./build/sem7 6` — `final`. Для расчёта T₁/T₆ можно передать свою медиану
   из этапа 1 в миллисекундах вторым аргументом после номера этапа.

Основное время перед `ms` — медиана пяти измерений после прогрева.
Число потоков показано в поле `threads`. Результаты выводятся в терминал,
таблицы заполняются в Word.

## Структура кода и проверки

- `multiply_ikj` и `multiply_ijk` — ядра умножения для диапазона строк.
- `measure_serial` и `measure_parallel` — два способа запуска и замера.
- `run_cases` — прогрев, повторные замеры и проверка произведения.
- `run_stage` — выбор одного из шести этапов.
- `main` — обработка аргументов и вызов выбранного этапа.

Элементы A равны 1, элементы B равны 2. При n = 800 каждый элемент C равен
1600. Проверка после каждого прогона подтверждает это значение. Программа
сообщает об ошибке в терминале и возвращает ненулевой код завершения.
CTest проверяет однопоточный режим, атомарный старт, неверный номер этапа,
нулевое базовое время и лишний аргумент. Для проверки форматирования можно
выполнить `clang-format --dry-run --Werror main.cpp`.
